## Things you must not get wrong

1. **`resolvedText` is the ONLY sanctioned reader of block text.** `Block.text` keeps the
   *unrepaired* reading permanently, by design (deviation D4). Every consumer reads unrepaired
   text unless it applies proposals itself. **No epic may concatenate `text` and `repairs` by
   hand.** Use `resolvedText(block, {applyProposed})`.

2. **Do not paint highlight quads straight from `span.bbox`.** 17 spans in the `resnet` fixture
   are ~7.33 pt too tall downward, because the line contains a CMSY10/CMMI10 run and MuPDF
   reports that run's *font* box rather than its glyphs'. That produces 18 places where one
   line's span box overlaps the next line's by ~5.2 pt. **Clamp to the typographic line band.**
   Block-level polygons are correct.

3. **`text` is never de-hyphenated.** `transduc-\ntion`, and 61 line-break hyphens in `resnet`
   alone. A reflow view must handle `-\n`.

4. **The three fixtures deliberately disagree** on (a) whether a page-range slice is `complete`
   or `partial`, (b) whether front matter belongs to a `Section`, (c) whether a display
   equation's `(n)` tag is part of its `text`. A reader that hard-codes one convention breaks
   *here*, on a test, rather than in production. **Do not "fix" the disagreement.**

5. **A tier-1 `block_id` hit MUST be confirmed against `content_hash`** before you trust it.
   The id hashes only the block's top-left anchor, so a block that grows downward keeps its id.
   Measured: under a paragraph merge, 665 of 5 670 blocks (11.73 %) inherit an id onto *changed
   text*; under a split, 1 752 (30.9 %). `content_hash` catches 100 % of them. A tier-1 hit
   returned without that check is a silent misresolution.

6. **ADR-004's multi-selector anchor is MANDATORY, not optional.** A segmenter change loses
   **42.2 %** of ids corpus-wide, of which 35.75 pp is a floor no formula can beat. Block ids are
   anchoring tier 1 only. Per-paper merge churn spans 14.9 % (attention) to 66.1 %
   (a3c) — size your re-anchor tooling for the worst paper, not the mean.

7. **DESIGN.md §11.4 assigns you a promise.** `EquationPayload.latex`/`mathml` and
   `TablePayload.html` accept arbitrary strings, and that is acceptable *only because* "the UI
   is obliged to render them in the 'our reading' register" — **Epic 2 owns that promise.** The
   required `image` is the ground truth. If you render latex as if it were the paper, the
   schema's whole interpretation-vs-source distinction collapses.

8. **`pnpm test` is not a gate.** turbo's `test` inputs are package-relative with no
   `globalDependencies`, and runs are cached — the gate observed a cache hit reprinting results
   without executing. Run suites directly when you need a real signal, or `turbo run test --force`.

9. **CI will not run on your PRs.** The `pull_request` trigger lists only
   `[main, epic-0-spine]`. `.github/workflows/**` is Epic 0's — open an issue to add
   `epic-2-reader`. `main` has no branch protection either.

- **No `Repair`, no `Alternative`, no `Derivation`, no model authorship anywhere.** The

- **Block types absent entirely:** `list`, `list_item`, `code`, `citation`, `reference_entry`,

  relation beyond `parent_of`. Only five types are present.
- **Figure interiors are not addressable** — axis labels and legend text are at most
  `payload.detected_labels`, never blocks.
- **Rotated text is geometry only** — no field records that glyphs are rotated 90°; infer it

- **Present exactly once, so do not assume redundancy:** one table (1 table / 5 rows / 24 cells,

path.

## Hard rules

- Highlight geometry is **quads in PDF user space** against
  `getViewport({scale: 1, rotation: 0})`, painted through a `transform: scale(z)` overlay.
  **Never `getClientRects()`/`window.innerWidth`** — that is the current bug that makes every
  stored highlight unrecoverable. Note `convertToViewportRectangle` no longer exists in current
  pdf.js — convert per point with `convertToPdfPoint`. Handle `userUnit` and page rotation.
- **Regions are polygons, not rectangles.** Use `unionOfLineRects`; a selection crossing a
  two-column gutter must produce **two** polygons, never a box over the gutter. Epic 0 shipped
  and then fixed exactly this bug — do not reintroduce it downstream.
- **Guided content is never presented as the paper.** Distinct type register, a reserved `⊙`
  marker used nowhere else, `derived_from` block ids on every block, a working "show source" on
  each. There must be a test that fails if a Guided block renders without these.
- **No fabricated diagrams.** Mermaid is deleted, not restyled. A derived section that wants to
  show structure shows the paper's own figure crop.
- The outline is PaperIR's **section tree**, never a page list.
- Pointer Events, not mouse events. Nothing hover-only. 44 pt minimum targets.
- Bundle the pdf.js worker **locally**; never from a CDN.
- No new runtime dependency without a one-line justification in the PR body.

## The criterion that matters most

**`anchoring/reparse.spec`: ≥99 % of highlights must re-anchor when block ids change under a
perturbed parse, and every failure must be visible to the user.**

If this cannot be met, **stop and say so rather than lowering the bar.** The whole architecture
rests on annotations surviving parser upgrades. `research/build/README.md` makes this the
build's architectural gate criterion 3: if it fails, everything downstream must stop.

Note the arithmetic you are up against: a segmenter change loses 42.2 % of ids outright, so 99 %
re-anchor is only reachable through tiers 2–4 (content hash, text quote, geometric overlap) with
loud failure for the remainder. Design for that from the start.
