## The real API surface you are consuming

Verified against `ae5c99f` by the gate, not quoted from a doc.

**`@papertree/document-ir`** — TS package, plus a Python twin `papertree_document_ir`.
Everything under `src/generated/` is generated from
`schema/paperir-1.0.0.schema.json`; never hand-edit it.

- `identity`: `blockId(input)` / `block_id(BlockIdInput)` where the input is exactly
  `{source_hash, page_index, x0, y0, block_type, text}`. Also `normaliseText`,
  `contentHash`, `quantise`, `resolvedText(block, {applyProposed})`, plus the frozen constants
  `GRID_PT`, `TEXT_PREFIX_CODEPOINTS`, `CASE_FOLD_UNICODE_VERSION`.
- `geometry` (34 exports): `normalisePageFrame`, `normalisePoint`, `normaliseRect`,
  `normalisePolygon`, `stripUserUnit`, `pdfToViewport` / `viewportToPdf`, `polygonExtent`,
  `bboxMatchesPolygonExtent`, `pointInPolygon`, `polygonsIntersect`, `bboxToPolygon`,
  **`unionOfLineRects`** / `union_of_line_rects`.
- `validate`: `validatePaper` → `{diagnostics}`, `assertValidPaper`, `SEMANTIC_RULES`.
  A document that passes Zod/Pydantic is well-**formed**; one that also passes `validatePaper`
  is well-formed **and internally consistent**. Emit only documents that pass both.
- `canonical`: `canonicalJson`, `canonicalJsonForDeterminism` — this is what your
  `worker/determinism.spec` byte-identity claim must be built on. The gate verified TS and
  Python agree on number formatting including `-0.0`, `1e-7`, `5e-324` and
  `792.00000000000006`.

**`papertree_db`** (Python; `@papertree/db` in TS). `PaperTreeDb`, `openDatabase`, `migrate`.
**Every query helper takes an `OwnerId` as its first argument.** `owner_for(user_id)` performs
**no authentication** — it only checks a `users` row exists. The caller is the trust boundary.
Papers are keyed `(paper_id, generation)` and blocks `(paper_id, generation, block_id)`, because
content-derived ids are identical across generations by design.

**`papertree_jobs`** (Python only). `JobRunner`, `JobContext`, `JobStore`, `backoff_delay`,
`Cancelled`, `LeaseLost`. Per-step checkpointing: a step whose record is `succeeded` is never
re-run. `ctx.progress(done, total, note)` both publishes progress **and** renews the lease;
`ctx.check_lease()` raises `LeaseLost`. Parsing must run through this.

## Hard rules

- **Emit PaperIR exactly as the schema specifies.** Never invent fields. If the schema is wrong,
  open an issue — do not edit `packages/document-ir`.
- **No LLM output ever enters a source field.** `SourceKind` is
  `pdf_text_layer | pdf_vector | pdf_raster | ocr` and has no model value **by design**. A VLM's
  reading is a `Repair` (`applied: false`, obliged to name its model and carry a `prompt_hash`)
  or an `Alternative` (`authored_by: "model"`, obliged to be `not_selected`). The crop is always
  retained as ground truth.
- **Geometry is PDF user space, origin top-left, normalised once at parse time.**
  `/Rotate` applied, CropBox-relative, **`/UserUnit` NOT applied** — MuPDF's `page.rect` is
  pre-multiplied by `/UserUnit` while `mediabox`/`cropbox`/`rotation_matrix` are not, so divide
  it back out exactly once with `stripUserUnit`. Getting this wrong costs **99.93 %** of ids.
- **Regions are polygons, not rectangles.** Use `unionOfLineRects`; never a bounding box over
  multiple lines. A selection crossing a two-column gutter must return **two** polygons.
- **Unclassifiable regions become `unknown` with geometry intact** — never dropped.
- **Every text mutation is a recorded `Repair`** with `from` and `to`. No silent mutation. (The
  old code rewrote U+2212 MINUS to ASCII hyphen invisibly.)
- **A tier-1 `block_id` hit MUST be confirmed against `content_hash`.** The id hashes only the
  top-left anchor, so a block that grows downward keeps its id: under a merge, 665 of 5 670
  blocks (11.73 %) inherit an id onto *changed text*; under a split, 1 752 (30.9 %). Verifying
  `content_hash` detects 100 % of them.
- Parsing runs as a durable job via `packages/jobs`, resumable per step.
- No new runtime dependency without a one-line justification in the PR body.
